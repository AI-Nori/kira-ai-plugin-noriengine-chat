# NoriEngine Chat

KiraAI 群聊增强插件。所有消息都进入会话缓冲，由评分引擎逐条判定"现在值不值得开口"——强信号立即回复，弱信号静默累积，喧宾夺主时自动克制。

> ⚠️ 本插件与内置 **默认聊天（default-chat）** 互斥，启用前请先在 WebUI 停用默认聊天。

## 功能特性

### 强信号直通
- **@AI**：100 分直接信号，单条即触发
- **提及**（唤醒词命中 / 引用回复AI）：80 分直接信号
- **私聊**：40 分基础 + 概率门控（默认每条必回）

### 话题聚焦（默认关闭）
WebUI 独立配置分区"话题聚焦"，包含两个特性与一个统一生效范围。

#### 话题延续
开启后（`话题延续窗口（秒）` > 0），**bot 回复后 N 秒内到达的每条被评分的群消息**都获得"话题延续"直接信号档（默认 50 分，介于提及 80 与私聊 40 之间），并解锁仅直接上下文生效的请求/征询词检测——延续话题的"帮我看看"本就是对 bot 说的。窗口以 bot 最后一条回复为锚，新回复重新起算；**窗口内所有消息均计分，不只第一条**。

单条延续消息（50+积压6 ≈ 56）到不了默认阈值 80，静默累积；两条延续、或一条叠内容信号（问题/请求/长文本）即触发。防刷屏约束不变：触发后累积分清零、busy 串行化限制并发、存在感抑制上限 -25 仍生效——持续延续话题是真人主动行为，抑制随对话升温自然形成节奏刹车。延续消息落在 LLM 回合进行期间时按 busy 规则入队，回合结束后随挂起触发统一刷出。

#### 话题聚集感知
开启开关后，**统计窗口（默认 30 秒）内 ≥N 个不同发送者（默认 3 人）参与讨论、且至少一条非低价值内容**时判定"话题热度"成立——之后每条被评分的消息额外获得聚集加分（默认 50）。判定只看此前的参与者：当前消息不会"自己凑满人数还给自己加分"；同一人刷屏不计人数（去重）；戳一戳无讨论内容、不计入参与者。热度自刷新：窗口滑出后回落普通评分。

聚集加分是**独立加分项**（非直接信号档，不解锁请求/征询词检测），且**累积时原值入账、不受群聊累积概率稀释**（与戳一戳基础分同规则）——若按概率 ×0.5 累积，50 分实际只加 25，加速效果就没了。数值上：50 + 积压封顶 30 = 80 恰好达到默认阈值（3 人 5 秒内密集讨论后下一条消息立即触发）；分散讨论（积压 6~22）时单条 56~72 静默累积，两条即触发。存在感抑制仍照常扣减，作为刷屏刹车。

#### 生效范围
`话题聚焦会话` 是两个特性的**统一生效范围**：留空时全局生效；配置了会话 ID 列表时仅列表中的会话同时启用话题延续与话题聚集感知（每行一个，见日志 `sid=` 或 WebUI 会话管理页）。

### 弱信号评分累积
普通群聊消息按内容逐条评分，乘以群聊累积概率后累加，**累积分达到阈值即触发回复**（默认 80 分）。评分维度：

| 信号 | 分值 | 说明 |
|---|---|---|
| @AI | +100 | 最高优先级 |
| 提及（唤醒词/引用回复） | +80 | 文本包含唤醒词即命中 |
| 话题延续（窗口内每条） | +50 | 话题延续窗口开启时，bot 回复后 N 秒内的每条群消息；解锁请求/征询词检测 |
| 话题聚集（热度中每条） | +50 | 聚集感知开启且窗口内 ≥N 人含非低价值内容时；独立加分项，累积不受时段概率稀释 |
| 提问（"怎么/如何/为什么/吗？…"） | +15 | 过短语气片段（≤4 字）不计 |
| 请求（"帮我/帮忙/能不能…"） | +20 | 弱请求词仅在直接上下文生效 |
| 征询意见（"你觉得/怎么看…"） | +20 | 仅在直接上下文（@/提及/私聊）中生效 |
| 长文本 | +5 ~ +15 | ≥40 字 +5，≥120 字再 +10 |
| 语音/图片/视频 | +15 | 消息携带语音、图片或视频段时给固定分，并豁免低价值扣分 |
| 文件/合并转发 | +10 | 消息携带文件或合并转发段时给固定分，并豁免低价值扣分；与语音/图片/视频同在时取高档不叠加 |
| 低价值短语（"哈哈/6/嗯"整批） | -25 | 整批消息均为短反应时扣分（携带上述任一媒体段时豁免；表情包不豁免，仍按反应类处理） |
| 积压压力 | 0 ~ +30 | 近 5 秒外部消息 1/2/≥3 条 → 6/22/30 分（5 秒内 3 条算满批次）；**全局上限 30**，不随时段概率缩放 |
| 存在感抑制 | 0 ~ -25 | AI近期发言占比过高时自我克制 |
| 闲时补偿 | +15 | 会话空闲超过平均发言间隔时 |
| 节奏系数 | ×0.5 ~ ×1.0 | 整体缩放，控制AI活跃程度 |

> 开头点名其他 AI（如"DeepSeek，帮我…"）且未提及时，不视为对AI的请求。
>
> **强信号保护**：积压分全局封顶 30，普通群聊消息（无 @/提及）的内容分上限为 65（问题+请求+长文本+媒体最高档；文件/转发为低档，不与高档叠加），两者合计至多 95——刷屏本身凑不出"假强信号"（孤立单条至多 65+6=71 分），仅"内容信号拉满且 5 秒内 ≥3 条突发把积压抬到顶格"的极端组合才可能越过阈值。时段概率不作用于评分本身，只在弱信号累积时加权。

### 活跃时段调度
按时间段覆盖群聊/私聊概率，支持跨午夜（`23:00-08:00`）。概率为 0 的时段**完全休眠**（强信号同样被抑制），适合配置深夜免打扰。多个时段重叠时按配置顺序取**第一个命中**的规则；时段判定使用 WebUI `locale.TZ` 配置的时区（未配置时为服务器本地时区）。

### 存在感抑制
统计最近窗口内AI发言占比：低于 25% 不惩罚，25%~60% 线性升压，最高扣 25 分——避免AI在群里刷屏。满抑制叠加孤立单条的积压（6 分）时，孤立的提及（80 分）会被压到 61 分而暂不触发，需内容信号或突发积压补足，或经弱信号累积触发——AI 刚刷完屏时连提及也会收敛。

### 合并窗防抖
触发后不立即回复，等待短暂合并窗（默认 2 秒）收集同一突发的后续消息，一并送入 LLM 生成单次回复；等待期内再次触发会自动顺延。

合并窗内到达的消息既随本回合一并送入 LLM，也会照常积入累积分——这是**话题热度惯性**的有意设计：话题正热时，下一轮触发门槛更容易跨过。与 busy 挂起期间不积分不同（挂起消息由回合结束后的统一刷出带走，不重复计分）。

### LLM 回合串行化（busy 队列）
宿主按会话**并发**派发批处理事件——若 LLM 回合进行中（数秒到数十秒）又有消息触发阈值，会并发开出第二轮 LLM：第二轮读不到第一轮的回复（旧记忆竞态）、两轮回复交错、历史乱序、token 翻倍。本插件对此串行化：

- **触发挂起**：回合进行期间（从刷出发布起，到回合结束钩子触发止）的新触发不并发开新回合，挂起等待且**累积分保留不清零**，后续消息持续进入 busy 队列（默认上限 10 条，超出裁剪最旧）；
- **回合结束放行**：宿主在每轮批处理的 agent 循环结束后分发 `on_final_result` 钩子（v2.34.4+，先于会话记忆落盘、无条件触发），以此作为精确的回合结束信号——挂起的触发经合并窗统一刷出，下一轮自然读到上一轮的回复；
- **看门狗兜底**：回合结束信号失联（如未配置默认 LLM 的早退路径）时，超时（默认 60 秒）强制放行，不会挂死会话；新回合开始（LLM 请求事件）也会自愈陈旧的 busy 标记。

> ⚠️ **看门狗超时应配置为大于最慢一轮 LLM 回合（含工具调用与多段回复）的耗时**。若某轮实际耗时超过该值，看门狗会提前放行挂起的触发、与仍在进行的回合并发；且旧回合迟到的结束信号会误释放新回合的 busy，使串行化在连续对话期间持续失效（出现空闲间隙后自愈）。回合普遍偏慢的部署建议调大此值（5-300 秒）。

代价是回合期间的 @AI 不再即时回应，需等上一轮结束——串行、一次说完一段话，更接近真人节奏。

### 戳一戳
被戳不直接触发回复，改为**按基础分累积评分**（默认 30 分/次，不受时段概率影响），累积达到阈值（默认 80，即第 3 次被戳）才触发 LLM 回复；群聊私聊同一套逻辑。休眠时段（概率为 0）不积分、不回戳。

未达阈值时可启用**机械回戳**（默认关闭）：自动戳回发起者。控频三重约束：

- **全局冷却**（默认 3 秒）：多人/多会话同时戳共用同一节流窗口；
- **会话连续上限**（默认 3 次）：累计机械回戳满后仅保留积分累积，由回复阈值接管——打断两个自动回戳 bot 之间的无限互戳；
- **回复清零**：AI 产生任意回复时连续计数清零，重新校准额度。

识别按事件结构（`notify/poke` + 被戳者为 AI 自身）判定，不绑定具体平台；出站回戳依赖渠道客户端的 `send_poke` 能力，不支持时自动跳过。

## 安装

```bash
# 1. 复制插件目录到 KiraAI 插件目录
scp -r kira-ai-plugin-noriengine-chat <服务器>:/data/KiraAI/data/plugins/

# 2. 在 WebUI 插件管理页：
#    - 停用「默认聊天」(default-chat)
#    - 启用「NoriEngine Chat」
```

无需重启，插件通过热重载生效。

## 配置说明（WebUI 可视化）

### 基础设置
| 配置项 | 默认值 | 说明 |
|---|---|---|
| 唤醒词 | （空） | 消息文本包含任一唤醒词即视为提及（+80 直接信号）；需要昵称触发时把昵称加入唤醒词即可 |
| 上下文缓冲上限 | 5 | 未触发回复的消息保留条数，触发时随上下文送入 LLM |
| 群聊追加提示词 | （空） | 群聊批次送入 LLM 前追加到环境提示词末尾 |

### 触发评分
| 配置项 | 默认值 | 说明 |
|---|---|---|
| 触发阈值 | 80 | 单次评分或累积分达到即回复；越高越沉默 |
| 群聊累积概率 | 0.5 | 弱信号每条按"评分 × 概率"累积；0 为完全休眠 |
| 私聊回复概率 | 1.0 | 私聊每条独立判定；1 为每条必回 |
| 回复节奏系数 | 1.0 | 越大越积极（整体缩放 + 积压更敏感），建议 0.5-2.0 |
| 合并等待（秒） | 2.0 | 触发后合并后续突发消息的窗口 |
| busy 队列上限（条） | 10 | LLM 回合处理期间的会话缓冲上限（超出裁剪最旧），回合结束后统一刷出 |
| busy 看门狗超时（秒） | 60 | 回合结束信号失联时的兜底上限：超过该时长强制放行挂起的触发（5-300）。**应大于最慢一轮 LLM 回合的耗时**，否则串行化会被提前打断 |
| 突发统计窗口（秒） | 5.0 | 最近 N 秒消息条数计为积压量 |
| 活跃时段（每行一条） | （空） | 格式 `HH:MM-HH:MM`，跨午夜写 `23:00-08:00` |
| 时段群聊概率（每行一个） | （空） | 第 N 行对应第 N 个时段，缺失回退 0.5 |
| 时段私聊概率（每行一个） | （空） | 第 N 行对应第 N 个时段，缺失回退 1.0 |

**时段配置示例**（三个列表按行对齐）：

```
活跃时段：        时段群聊概率：   时段私聊概率：
08:00-23:00      0.5             1.0
23:00-08:00      0               0.2
```

表示白天正常聊天，深夜群聊完全休眠、私聊 20% 概率回复。

### 话题聚焦
| 配置项 | 默认值 | 说明 |
|---|---|---|
| 话题延续窗口（秒） | 0（关闭） | 话题延续：bot 回复后 N 秒内的每条群消息获得直接信号加分（0-300） |
| 话题延续基础分 | 50 | 窗口内每条消息的直接信号分：介于提及(80)与私聊(40)之间；单条不触发，叠内容信号或两条即触发 |
| 启用话题聚集感知 | 关闭 | 总开关：窗口内 ≥N 人讨论且含非低价值内容时，热度中的每条消息获得聚集加分 |
| 聚集统计窗口（秒） | 30 | 最近 N 秒内的不同发送者人数与内容质量参与聚集判定（0-600） |
| 聚集人数下限 | 3 | 窗口内不同发送者达到该人数（且至少一条非低价值内容）才判定热度成立 |
| 聚集加分 | 50 | 热度中每条消息的额外加分：独立加分项，累积原值入账不受时段概率稀释；50+积压30=80 恰达默认阈值 |
| 话题聚焦会话 | （空） | **两个特性的统一生效范围**：留空全局生效，否则仅列表中的会话同时启用话题延续与话题聚集感知（每行一个会话 ID） |

### 信号词表
提问词、请求词、征询词、低价值短语、其他 AI 名单——全部可视化编辑（每行一个），留空恢复默认。

### 存在感抑制
| 配置项 | 默认值 | 说明 |
|---|---|---|
| 统计窗口（条） | 20 | 取最近 N 条消息计算AI发言占比 |
| 时间衰减（分钟） | 10 | 仅统计最近 N 分钟；0 为只用条数窗口 |

### 戳一戳
| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启用戳一戳门控 | 开 | 被戳不直接触发回复，按基础分累积评分（不受时段概率影响）；关闭后走普通消息评分 |
| 戳一戳基础分 | 30 | 每次被戳累积的分数（默认阈值 80，即第 3 次被戳触发回复） |
| 机械回戳 | 关 | 累积未达回复阈值时自动戳回发起者 |
| 回戳冷却（秒） | 3.0 | 全局冷却：多人/多会话同时戳共用同一节流窗口 |
| 连续回戳上限 | 3 | 会话级连续机械回戳次数上限，累计满后仅保留积分；AI 产生任意回复时清零，0 为不限制 |

## 日志观测

```bash
# 触发行为（INFO 级）
grep NoriEngineChat /data/KiraAI/data/log.log

# 静默累积明细（DEBUG 级）
grep "静默累积" /data/KiraAI/data/log.log
```

日志包含每次评分的完整分项明细，例如：

```
[NoriEngineChat] 强信号触发: sid=napcat:gm:1105211570 最终=125 原始=125 直接信号=80(提及) 内容=15(问题) 积压=30 节奏=1.000 倍率=1.00
[NoriEngineChat] 累积触发: sid=napcat:gm:1105211570 accumulated=90.0 (最终=45 原始=45 内容=15(问题) 积压=30 节奏=1.000 倍率=1.00)
[NoriEngineChat] 静默累积: sid=napcat:gm:1105211570 score=45 acc=4.5/80 内容=15(问题) 积压=30 节奏=1.000 倍率=1.00
```

> 积压分不随时段概率缩放；时段概率只作用于弱信号累积加权（`acc` 的增量 = 评分 × 概率）。
